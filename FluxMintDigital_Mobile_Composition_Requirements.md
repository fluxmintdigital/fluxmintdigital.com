# FluxMintDigital Mobile Composition Requirements

**Decision status:** REQUIREMENTS RESOLVED — RENDERS NOT YET PRODUCED. Missing renders are expected asset-production outputs, not readiness blockers.

## Global contract

Mobile uses deliberate compositions, never automatic desktop crops. Each image must preserve the same place, Room verb, identity, and primary action while allowing objects to move or simplify. Semantic navigation, search, breadcrumbs/location receipt, object labels, state, and content remain HTML/SVG/components outside the raster. Touch targets must not depend on hover; scene failure must leave complete semantic access. No new pets appear outside the approved Library treatment.

## Mobile state and asset requirements

- Every scene requires an explicitly reviewed mobile base or a documented non-image composition; producing these is authorized later asset-production work.
- Desktop hotspot percentages are invalid as mobile specifications. Each mobile composition receives independent target mapping and semantic reading order.
- Text in direction specimens is not safe space merely because it is currently printed into the PNG; production text must be removable/reflowable live UI.
- Character assets require mobile-aware placement/derivation. Do not horizontally squeeze, mirror insignia/text, or crop faces/hands essential to the pose.
- Architecture Wall may transform from a literal wall into a focused inspection view. Semantic equivalence outranks reproducing all desktop nodes.
- Main Studio and Outfitters may prioritize fewer visible objects, but all destinations/actions remain accessible through semantic controls.
- Reduced-motion mode keeps every action and state available without Ken Burns, smoke, glow pulsing, reveal gating, connector drawing, parallax, or scroll-linked rotation.
- Mobile may move, simplify, hide or reframe decorative objects, but must never remove Room identity, primary action, semantic navigation, required accessible controls, essential Artifact access, or return/orientation.
